# TAM AN CARE V7.4.3
## STEP 7Q — Activities / Rehabilitation / Functional Support Management

### Purpose

STEP 7Q provides accountable operational management for:

- social and recreational activities;
- mobility and functional-support activities;
- rehabilitation-support sessions;
- range-of-motion and functional-maintenance activities;
- supervised walking / transfer practice;
- participation and attendance;
- functional observation and assessment;
- resident refusal / missed participation;
- safety restrictions and precautions;
- functional-support escalation;
- auditable correction and human review.

This domain does NOT independently diagnose disease,
prescribe rehabilitation treatment,
set medication,
override clinical restrictions,
or make emergency decisions.

### Canonical flow

Resident
-> Activity Program / Rehabilitation Plan
-> Human approval
-> Activity / Rehabilitation Session
-> Human assignment
-> Human acceptance
-> Safety / restriction check
-> READY
-> Supported activity / rehabilitation execution
-> Participation / attendance result
-> Functional observation / assessment
-> Optional explicit human escalation
-> Resolution
-> Audit

### Core separation

Activity / rehabilitation data remains a distinct domain.

No automatic conversion from:

- AI alert to Care Action;
- Activity Session to Care Task;
- Functional Assessment to Medication mutation;
- Functional decline to Incident;
- Functional concern to Clinical treatment;
- missed participation to Care Action.

Any cross-domain action requires an explicit,
authorized human command in the target domain.

### Human accountability

Official lifecycle mutations require an attributable human actor.

Existing operational roles remain:

- CAREGIVER
- NURSE
- SUPERVISOR
- CARE_MANAGER

Role specialization may be represented through staff profile /
competency metadata later without changing the core STEP 7Q
human-accountability contract.

### Clinical / rehabilitation boundary

STEP 7Q supports execution and documentation of
human-approved activities and functional support.

It does not autonomously determine:

- diagnosis;
- rehabilitation prescription;
- therapy intensity;
- exercise progression;
- exercise restriction;
- weight-bearing status;
- transfer status;
- fall-risk treatment;
- medication changes;
- emergency transfer.

### AI boundary

AI may:

- detect participation trends;
- detect possible functional decline patterns;
- summarize activity history;
- suggest candidate activities for human consideration;
- suggest scheduling options;
- generate advisory alerts;
- identify possible documentation anomalies.

AI may not:

- activate a rehabilitation plan;
- prescribe an exercise;
- determine exercise intensity;
- remove a restriction;
- create an official functional assessment;
- verify an assessment;
- assign itself or SYSTEM as accountable owner;
- mark a session completed;
- record resident refusal as an official fact;
- resolve an escalation;
- mutate Medication / Clinical / Incident / Care Action domains.
