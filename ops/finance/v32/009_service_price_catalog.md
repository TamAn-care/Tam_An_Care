# Finance V1.1 service price catalog

`009_service_price_catalog.sql` adds an empty, versioned VND price catalog. It contains no seed or backfill and must only be qualified in isolated PostgreSQL 16 until a separately approved release. Catalog versions store dated items (service code, scope, unit and whole VND amount); malformed/negative amounts, invalid ranges and duplicate service/scope items fail closed.

Drafts may be revised by their creator. Submission requires a different authenticated actor, and approval/rejection requires a third party relative to the submitter. Approved terms cannot be edited. Approval rejects overlapping effective periods for the same service code and scope across catalog versions. Audit rows are immutable and include actor ID, role when set by the API, action, reason and timestamp. No destructive down migration is provided; before business writes the safe rollback is restoring a verified pre-migration backup in isolation. After writes, retain audit and use an approved forward correction.

`ServicePricingController` exposes a server API for listing, drafting, editing, copying an approved/rejected version into a draft, submitting and deciding. Every call requires a verified JWT identity, active DB session and active staff actor. Server permissions mirror the existing approved `role-policy.ts`: ADMIN/SUPERVISOR can approve; CARE_MANAGER can view/manage drafts/submit but cannot approve; ACCOUNTANT can view approved prices only; clinical/guardian roles are denied. This role map is narrow to the pricing capability and does not grant discount approval, billing issue or P&L access.

The UI is connected to this API and does not present the legacy local pricing matrix as an authoritative source. New lists start with one item; draft editing supports adding/removing items and cloning approved versions. Contract price precedence, meal price mapping and billing snapshot integration remain release blockers. This change does not enable invoice generation or apply the migration to Production Test.
