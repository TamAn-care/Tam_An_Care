# TAM AN CARE V7.5
## STEP 9B — FRONTEND ARCHITECTURE CONTRACT

Status: LOCKED

---

# 1. Frontend stack

Canonical V7.5 frontend stack:

- React
- TypeScript
- Vite
- React Router
- TanStack Query
- lightweight local UI/session state
- CSS variables + component-scoped styles
- PWA-ready architecture

Do not introduce a large global state framework unless a later proven need exists.

---

# 2. Project boundary

Frontend SHALL be a separate application workspace.

Recommended root:

frontend/

The accepted V7.4.3 backend is not to be mixed into frontend source.

# 4. Application shell

The canonical shell contains:

- top header
- left navigation on desktop
- compact navigation on smaller screens
- page title area
- current user/role area
- connectivity/API health indicator
- content viewport
- global error surface

The shell must remain usable even when a feature API fails.

---

# 5. Routing strategy

Routes SHALL be explicit.

Initial vertical slice:

/
  -> dashboard

/dashboard

/residents

/residents/:residentId

/residents/:residentId/care

/staff-access

/system-status

Later domain routes extend from this base.

No route shall imply authorization solely because the route is visible.

Backend authority remains canonical.

---

# 6. State strategy

Server data:
TanStack Query.

Local interface state:
React local state/context.

Actor/session context:
dedicated ActorContext.

Do not duplicate server entities into global client state without evidence.

---

# 7. API client

One shared API client.

Responsibilities:

- base URL
- JSON handling
- canonical headers
- actor identity headers
- HTTP error normalization
- timeout handling
- connectivity failure mapping
- request correlation support where available

Components must not assemble raw authority headers independently.

---

# 8. Actor/session context

ActorContext owns:

- actorId
- actorRole
- display information
- session status
- signed-in/signed-out state

Initial human roles:

- CAREGIVER
- NURSE
- SUPERVISOR

AI and SYSTEM are never user-selectable human sessions.

Temporary development actor selection may exist only behind an explicit
development-only boundary and must not become the production authority model.

---

# 9. Navigation policy

Navigation visibility is role-aware for usability.

But hidden navigation is NOT a security control.

Every backend request must still pass backend authorization.

---

# 10. Error model

Canonical UI error states:

- 400 invalid input
- 401 session/identity required
- 403 authority denied
- 404 unavailable or non-disclosing resource
- 409 conflict
- 5xx server failure
- network disconnected
- request timeout

Messages must be understandable in Vietnamese.

404 must not disclose existence of unauthorized resident data.

---

# 11. Loading model

Every async screen SHALL support:

- initial loading
- background refresh
- empty state
- error state
- retry
- success state

Avoid full-screen blocking loaders for routine background refresh.

---

# 12. Responsive strategy

Desktop-first.

Breakpoints are behavior-based rather than device-brand based.

Target:

- >= 1200px full desktop shell
- 768–1199px compact desktop/tablet shell
- < 768px mobile responsive shell

Mobile web must preserve critical workflows.

---

# 13. PWA readiness

Architecture must support later PWA delivery.

Step 9B does not implement service workers yet.

No offline mutation queue is allowed until separately designed.

---

# 14. Accessibility baseline

Minimum:

- semantic HTML
- keyboard navigation
- visible focus
- form labels
- sufficient contrast
- readable typography
- meaningful status text
- no color-only safety indicator

---

# 15. Core vertical slice

The first frontend implementation sequence is:

Actor Context
-> Application Shell
-> Dashboard
-> Residents
-> Resident Care View
-> Staff & Access Administration

Broad domain UI comes only after this slice is accepted.

---

# 16. Security principle

The frontend is a presentation and interaction layer.

The backend remains the authority source.

Client-side role logic improves UX only.
It must never replace backend RBAC or canonical resident authorization.
