# Tam An Care V7.5 — STEP 9F.B Staff Read API Gap

## Finding

The canonical `StaffActorService` already contains bounded read functions:

- `findByActorId`
- `resolveCanonicalActor`
- `resolveActiveActor`
- `resolveActiveActorWithRole`
- `listStaffActors`
- `listActiveStaffActors`

However, the current locked backend does not expose a public HTTP StaffActor controller/route for the V7.5 frontend.

## Consequence

The frontend MUST NOT invent a staff endpoint.

The frontend MUST NOT read PostgreSQL directly.

The frontend MUST NOT use fixture or hard-coded staff data as an operational substitute.

## Existing public administration API

The existing resident access administration API remains authoritative for:

- assignment listing
- resident assignment listing
- assignment creation
- assignment revocation

## Required implementation decision

Before Staff List UI can be operational, one of the following must be explicitly approved and implemented:

1. expose a minimal read-only StaffActor HTTP API backed by the existing StaffActorService; or
2. reduce 9F scope so the UI operates only on information already exposed by access-assignment APIs.

Preferred architecture:

Expose a minimal read-only StaffActor API reusing the existing canonical StaffActorService.

No staff create/update/delete API is required.

No database schema change is required.

No direct database UI access is allowed.
