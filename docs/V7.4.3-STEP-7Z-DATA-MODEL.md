# Step 7Z — Canonical Eight-Table Data Model

## 1. fall_risk_assessments

Human assessment of fall-related risk factors.

Lifecycle:
DRAFT -> VERIFIED -> AMENDED

Verified assessment overwrite = NO.

## 2. mobility_support_plans

Human-approved mobility / transfer support plan.

Lifecycle:
DRAFT -> REVIEWED -> ACTIVE -> INACTIVE

Records:
- mobility support needs
- transfer-assistance level
- assistive-device context
- environmental support
- human owner
- human reviewer

## 3. transfer_safety_checks

Human transfer-readiness / safety check.

Lifecycle:
RECORDED -> VERIFIED

Transfer check does not authorize clinical treatment.

## 4. fall_events

Fall or near-fall factual event record.

Lifecycle:
OPEN -> ASSIGNED -> ACKNOWLEDGED -> RESOLVED -> CLOSED

Fall event does not itself establish injury diagnosis.

## 5. post_fall_observations

Human factual observation following a fall.

Lifecycle:
RECORDED -> VERIFIED -> AMENDED

No autonomous diagnosis.

## 6. fall_prevention_actions

Human-authorized non-pharmacological prevention / support action.

Lifecycle:
PROPOSED -> AUTHORIZED -> ACTIVE -> REVIEWED -> ENDED

No autonomous restraint.

## 7. fall_escalations

Human escalation workflow.

Lifecycle:
OPEN -> ASSIGNED -> ACCEPTED -> RESOLVED

Reviewer preservation required.

## 8. fall_audit

Append-only attributable audit history.

Requirements:
- same transaction
- human attribution
- unique entity sequence
- failed mutation = zero audit
- loser mutation = zero audit
