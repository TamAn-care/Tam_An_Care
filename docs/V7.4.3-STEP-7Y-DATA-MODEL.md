# Step 7Y — Canonical Data Model

Exactly eight tables are designed.

## 1. safeguarding_reports

Human-originated safeguarding concern.

Possible categories:

- suspected abuse
- suspected neglect
- suspected exploitation
- dignity concern
- rights concern
- privacy concern
- coercion concern
- financial concern

Report != proven finding.

Lifecycle:
REPORTED -> TRIAGED -> UNDER_REVIEW -> RESOLVED -> CLOSED

## 2. safeguarding_triage

Human safeguarding triage.

Records:

- immediate safety concern
- urgency classification
- resident protection need
- human rationale
- triage actor

AI cannot perform official triage.

## 3. protective_actions

Human-authorized temporary safeguarding measure.

Must preserve:

- necessity
- proportionality
- resident dignity
- resident rights
- reviewability
- human accountability

Protective action != disciplinary finding.

## 4. safeguarding_assignments

Accountable assignment of report/review ownership.

Lifecycle:
ASSIGNED -> ACCEPTED -> RELEASED

Owner identity must be preserved.

## 5. safeguarding_reviews

Human review / investigation record.

May contain:

- factual interview notes
- evidence references
- resident statement
- witness information
- review findings
- unresolved uncertainty

AI cannot determine final finding.

## 6. safeguarding_escalations

Human escalation workflow.

Lifecycle:
OPEN -> ASSIGNED -> ACCEPTED -> RESOLVED

Reviewer identity must be preserved.

## 7. safeguarding_post_reviews

Post-event governance review.

Examples:

- resident protection follow-up
- recurrence prevention review
- policy review
- staff support / training need
- environment / process issue

## 8. safeguarding_audit

Append-only attributable audit history.

Requirements:

- same transaction as official mutation
- unique sequence per entity
- human attribution
- loser mutation = zero audit
- failed mutation = zero audit
