# TAM AN CARE V7.4.3
# STEP 7P — NUTRITION / HYDRATION / MEAL & INTAKE MANAGEMENT

## Purpose

Provide accountable human-controlled nutrition, hydration,
meal assistance and intake documentation for residents.

The domain supports operational care while preserving a strict
boundary between observation/recommendation and clinical decision.

## Canonical domain flow

Resident
-> Nutrition Plan
-> Human-approved Diet Order
-> Meal / Hydration Schedule
-> Assignment
-> Human Acceptance
-> Meal / Fluid Assistance
-> Intake Record
-> Verification
-> Optional Amendment / Correction
-> Abnormal Intake / Hydration Alert
-> Human Acknowledgement
-> Optional Human Escalation
-> Resolution
-> Audit

## Core operational capabilities

1. Nutrition care plan
2. Diet order / dietary restriction
3. Allergy / intolerance documentation
4. Texture / consistency requirement
5. Meal scheduling
6. Hydration scheduling
7. Human feeding assistance
8. Meal intake recording
9. Fluid intake recording
10. Refused / missed / held intake state
11. Abnormal intake alert
12. Hydration-risk alert
13. Explicit escalation
14. Append-only audit
15. Amendment instead of silent overwrite

## Human accountability

All official nutrition or hydration mutations require
an attributable human actor.

AI may detect patterns and generate alerts or recommendations.

AI cannot:
- prescribe diet;
- change a diet order;
- impose or remove fluid restriction;
- determine feeding route;
- determine swallowing safety;
- override confirmed allergy or restriction;
- verify intake;
- sign care documentation;
- create clinical treatment;
- create Care Action automatically;
- create Care Task automatically;
- mutate medication;
- mutate clinical records;
- close escalation.

autonomousClinicalAction = false

## Safety principle

When safety information is missing or conflicting,
the system must fail closed for potentially unsafe
diet / fluid / feeding mutations.

No silent clinical assumption is permitted.
