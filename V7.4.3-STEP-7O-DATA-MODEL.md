TAM AN CARE V7.4.3
STEP 7O DATA MODEL DESIGN

DESIGN ONLY
NO TABLE CREATION IN STEP 7O.A

================================================
1. incidents
================================================

incident_id text PK

resident_id text nullable FK -> residents
incident_code text UNIQUE
incident_type text
title text
description text

occurred_at timestamptz nullable
discovered_at timestamptz
location text nullable

status text

reported_by text
reported_by_role text
reported_at timestamptz

current_severity text nullable

assigned_to text nullable
assigned_role text nullable
assigned_at timestamptz nullable

acknowledged_at timestamptz nullable

response_started_at timestamptz nullable
resolved_at timestamptz nullable
closed_at timestamptz nullable

resolution_summary text nullable

linked_care_action_id uuid nullable
linked_care_task_id text nullable
linked_clinical_observation_id text nullable
linked_medication_administration_id text nullable

created_at timestamptz
updated_at timestamptz

NO DELETE CASCADE.

================================================
2. incident_triage
================================================

incident_triage_id text PK
incident_id text FK -> incidents
resident_id text nullable FK -> residents

triage_sequence bigint
severity text
triage_summary text

triaged_by text
triaged_by_role text
triaged_at timestamptz

previous_triage_id text nullable

created_at timestamptz

Every re-triage is append-only.

================================================
3. incident_assignments
================================================

incident_assignment_id text PK
incident_id text FK -> incidents

assignment_sequence bigint

assigned_to text
assigned_role text

assigned_by text
assigned_by_role text
assigned_at timestamptz

ended_at timestamptz nullable
end_reason text nullable

created_at timestamptz

Assignment history is append-only.

Current owner is also reflected atomically on incidents.

================================================
4. incident_responses
================================================

incident_response_id text PK
incident_id text FK -> incidents
resident_id text nullable FK -> residents

response_sequence bigint

response_type text
response_note text

performed_by text
performed_by_role text
performed_at timestamptz

created_at timestamptz

Response documentation is append-only.

A response record documents a human action.
It does not authorize medication or diagnosis.

================================================
5. incident_escalations
================================================

incident_escalation_id text PK
incident_id text FK -> incidents

escalation_sequence bigint
escalation_type text
reason text

status text

escalated_by text
escalated_by_role text
escalated_at timestamptz

assigned_reviewer text nullable
assigned_reviewer_role text nullable
assigned_at timestamptz nullable

accepted_at timestamptz nullable

resolved_by text nullable
resolved_by_role text nullable
resolved_at timestamptz nullable

resolution_summary text nullable

created_at timestamptz
updated_at timestamptz

================================================
6. incident_post_reviews
================================================

incident_post_review_id text PK
incident_id text FK -> incidents

review_sequence bigint

review_summary text
contributing_factors text nullable
preventive_actions text nullable
follow_up_required boolean

reviewed_by text
reviewed_by_role text
reviewed_at timestamptz

created_at timestamptz

Post-review is a human governance record.

AI cannot sign it.

================================================
7. incident_audit
================================================

audit_id text PK
event_sequence bigint

incident_id text
resident_id text nullable

aggregate_type text
aggregate_id text

event_type text

actor_id text nullable
actor_role text nullable

previous_state jsonb nullable
new_state jsonb nullable

created_at timestamptz

UNIQUE:
incident_id + aggregate_type + aggregate_id + event_sequence

NO DELETE CASCADE.

================================================
INDEX DESIGN
================================================

incidents:
resident_id
status
incident_type
current_severity
assigned_to + status
occurred_at
discovered_at

incident_triage:
incident_id + triage_sequence

incident_assignments:
incident_id + assignment_sequence
assigned_to

incident_responses:
incident_id + response_sequence
performed_at

incident_escalations:
incident_id
status
assigned_reviewer + status

incident_post_reviews:
incident_id + review_sequence

incident_audit:
incident_id + created_at
aggregate_type + aggregate_id + event_sequence

================================================
CONSTRAINT PRINCIPLES
================================================

- assignment fields atomic
- timestamps consistent with lifecycle
- incident code unique
- no delete cascade
- append-only history where specified
- resident relationship validated when present
- explicit links must reference existing target records
- no automatic downstream object creation
