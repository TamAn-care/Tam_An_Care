TAM AN CARE V7.4.3
STEP 7O — INCIDENT / FALL / EMERGENCY MANAGEMENT

PURPOSE

Provide a human-accountable operational safety domain for:

- Incident reporting
- Fall reporting
- Suspected fall
- Emergency event reporting
- Near-miss reporting
- Injury / harm event reporting
- Environmental / facility safety incident
- Human triage
- Human assignment
- Human acknowledgement
- Response documentation
- Escalation
- Resolution
- Closure
- Post-incident review
- Immutable audit history

DOMAIN FLOW

Resident / Location / Event
-> Human Incident Report
-> Human Triage
-> Human Assignment
-> Assigned Human Acknowledgement
-> Human Response
-> Optional Human Escalation
-> Human Resolution
-> Post-Incident Review
-> Human Closure
-> Audit

AI FLOW

Sensor / AI / Monitoring System
-> Suspected Incident Alert
-> Human Review
-> Human Incident Creation if appropriate

AI ALERT IS NOT AN INCIDENT RECORD.

NO AI OR SYSTEM PROCESS MAY DIRECTLY:

- create an official incident record
- triage clinical severity
- assign staff
- acknowledge responsibility
- determine treatment
- determine medication
- determine hospital transfer
- contact emergency services autonomously
- resolve an incident
- close an incident
- sign a post-incident review
- create a Care Action automatically
- create a Care Task automatically
- mutate Medication / MAR
- mutate Clinical Observation data

autonomousClinicalAction = false

TYPE CLASSIFICATION DOES NOT ITSELF DETERMINE TREATMENT.

SEVERITY

Severity must use approved organizational configuration.

No hardcoded treatment threshold is permitted in application logic.

A severity classification is an operational triage record,
not a diagnosis and not an autonomous treatment instruction.

DOMAIN SEPARATION

Incident != Care Action
Incident != Care Task
Incident != Medication Administration
Incident != Clinical Observation
Incident != Diagnosis

Explicit human-authorized linking is permitted.

Automatic conversion is prohibited.

HUMAN ACCOUNTABILITY

Every mutating lifecycle event must record:

actorId
actorRole
timestamp
previousState
newState

Human ownership must remain attributable.

FAILURE ATOMICITY

Any rejected mutation:

business mutation = ZERO
audit mutation = ZERO

ROW LOCK

All state-changing operations must lock the target aggregate
before authorization and mutation.

CANONICAL ORDER

SELECT FOR UPDATE
-> NOT FOUND
-> AUTHORIZATION
-> TRANSITION VALIDATION
-> MUTATION
-> AUDIT
-> COMMIT
