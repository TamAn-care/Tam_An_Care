# TAM AN CARE V7.4.3
# STEP 8A.C — MINIMAL READ-ONLY INTEGRATION IMPLEMENTATION DESIGN

STATUS: DESIGN LOCK CANDIDATE
APPLICATION IMPLEMENTATION: NOT STARTED

---

## 1. OBJECTIVE

Define the smallest safe implementation unit for the
Step 8 cross-domain integration layer.

The first implementation SHALL be:

- resident-centric;
- read-only;
- provenance-preserving;
- partial-failure tolerant;
- authorization-preserving;
- AI-advisory only;
- non-clinical-authority-bearing.

No source domain ownership is transferred.

---

## 2. PROPOSED MODULE

Proposed future module:

api/src/cross-domain-integration/

Candidate files:

cross-domain-integration.module.ts
cross-domain-integration.controller.ts
cross-domain-integration.service.ts
cross-domain-integration.types.ts

Optional adapters MAY later be introduced under:

cross-domain-integration/adapters/

No adapter may mutate a source domain.

---

## 3. FIRST API SURFACE

Minimal candidate endpoint:

GET /api/integration/residents/:residentId/summary

Purpose:

Return one normalized, read-only resident-centric
cross-domain projection.

No POST.
No PUT.
No PATCH.
No DELETE.

Step 8A implementation begins with GET-only behavior.

---

## 4. RESPONSE ENVELOPE

Candidate conceptual structure:

{
  residentId,
  generatedAt,
  integrationMode: "READ_ONLY",
  domains: {},
  alerts: [],
  pendingHumanReviews: [],
  aiAdvisories: [],
  availability: {},
  provenance: []
}

This structure is a projection, not a clinical record.

---

## 5. NORMALIZED DOMAIN ITEM

Every normalized item SHOULD carry:

{
  sourceDomain,
  sourceEntityType,
  sourceEntityId,
  residentId,
  sourceTimestamp,
  sourceStatus,
  sourceAuditReference,
  data
}

Required invariant:

No normalized item may lose its source identity.

---

## 6. DOMAIN AVAILABILITY MODEL

Each domain SHALL report one of:

AVAILABLE
EMPTY
UNAVAILABLE
ERROR
STALE

EMPTY means the domain responded successfully but
contained no applicable resident information.

UNAVAILABLE means the source capability cannot currently
be reached or does not exist.

ERROR means an attempted source read failed.

STALE means data exists but freshness rules identify it
as potentially outdated.

These states MUST remain distinct.

---

## 7. READ STRATEGY

Preferred order:

1. Existing domain public service read method.
2. Existing domain summary/query contract.
3. Existing approved repository/database read pattern.
4. New read adapter only when required.

Direct cross-domain SQL SHOULD NOT be the default when an
existing domain service already owns the required query.

Integration SHALL NOT invoke source-domain mutation
methods.

---

## 8. DOMAIN ADAPTER CONTRACT

Conceptual adapter:

DomainReadAdapter {
  domain
  supportsResidentSummary()
  readResidentSummary(residentId, actorContext)
}

Adapter output:

DomainReadResult {
  domain
  availability
  items
  warnings
  provenance
}

No adapter write method is permitted in Step 8A.

---

## 9. INITIAL DOMAIN SCOPE

The minimal implementation SHOULD begin with a limited
representative set rather than all domains simultaneously.

Wave 1 candidate domains:

- residents
- clinical-observations
- care-plans
- care-tasks
- medication
- incidents

Reason:

These provide sufficient cross-domain coverage to prove:

- resident aggregation;
- clinical observation visibility;
- planned care visibility;
- task visibility;
- medication visibility;
- incident visibility.

Additional Step 7 domains can then be onboarded through
the same adapter contract.

---

## 10. AUTHORIZATION MODEL

Integration SHALL NOT create broader access.

actorContext MUST be propagated where the underlying
domain requires actor/user/role information.

Rule:

INTEGRATION ACCESS <= SOURCE DOMAIN ACCESS

If authorization cannot be safely inherited for a domain,
that domain SHALL return UNAVAILABLE or an authorization
failure rather than bypass source controls.

---

## 11. AI CONTRACT

AI output may be included only as advisory context.

AI result SHALL be visibly distinguishable from
source-domain clinical facts.

AI SHALL NOT:

- change normalized source facts;
- create a diagnosis;
- alter medication;
- create an official clinical action;
- resolve an incident;
- resolve safeguarding;
- authorize restraint;
- authorize transfer;
- bypass human review.

autonomousClinicalAction remains false.

---

## 12. ERROR ISOLATION

One failing domain SHALL NOT fail the complete resident
projection unless the resident identity itself cannot
be resolved.

Example:

residents = AVAILABLE
clinical-observations = AVAILABLE
care-plans = AVAILABLE
medication = ERROR
incidents = EMPTY

The integration response may still succeed while clearly
reporting medication=ERROR.

No synthetic medication state may be generated.

---

## 13. SOURCE-OF-TRUTH RULE

The integration response is a transient projection.

It SHALL NOT become authoritative over:

- clinical facts;
- medication state;
- care plans;
- care tasks;
- incidents;
- safeguarding;
- domain-specific governance state.

SOURCE DOMAIN STATE ALWAYS WINS.

---

## 14. AUDIT / PROVENANCE

Step 8A read-only implementation does not require a new
database audit table.

Read projection SHALL preserve available source audit
references.

If integration access logging is later required, it must
be designed separately and must not alter source-domain
audit history.

---

## 15. DATABASE IMPACT

Expected schema change for minimal Step 8A:

NONE.

Expected new business tables:

NONE.

Expected migration:

NONE.

If implementation discovery later demonstrates that a
schema change is required, implementation MUST STOP and
return to architecture review.

---

## 16. TEST STRATEGY

Minimum tests for first implementation:

1. Known resident returns resident-centric projection.
2. Unknown resident returns controlled not-found behavior.
3. Domain with data reports AVAILABLE.
4. Domain with no data reports EMPTY.
5. Failed domain does not fabricate data.
6. Failed domain does not necessarily fail whole projection.
7. Every returned item preserves provenance.
8. No POST/PUT/PATCH/DELETE integration endpoint exists.
9. Integration cannot mutate source-domain state.
10. AI advisory remains distinguishable from source facts.
11. Human-review state remains visible.
12. Existing source/domain regression remains green.
13. schema.sql hash remains unchanged.
14. Production remains untouched.

---
