# TAM AN CARE V7.5
## STEP 9B — DESIGN SYSTEM CONTRACT

Status: LOCKED

---

# 1. Design objective

The interface must feel:

- calm
- professional
- clear
- safe
- suitable for elderly-care operations
- easy for non-technical staff

Avoid dense enterprise dashboards that require technical training.

---

# 2. Language

Primary UI language:

Vietnamese.

Technical backend terms may appear only where operationally necessary.

Labels should describe staff actions, not implementation internals.

---

# 3. Core visual principles

- high readability
- clear hierarchy
- generous spacing
- obvious action states
- restrained decoration
- consistent forms
- clear warning severity
- safe destructive actions

---

# 4. Design tokens

Required token groups:

- typography
- spacing
- radius
- elevation
- border
- surface
- text
- primary action
- success
- warning
- danger
- information
- disabled
- focus

Tokens SHALL be implemented through CSS variables.

Feature components must not invent arbitrary visual values repeatedly.

---

# 5. Typography

Prefer a system-supported Vietnamese-safe sans-serif stack.

Requirements:

- full Vietnamese diacritics
- body text comfortable for daily staff use
- headings clearly distinguished
- no decorative font for operational information

---

# 6. Density

Default density:

comfortable.

Tables may use compact density selectively.

Critical care information must not be visually compressed.

---

# 7. Component families

Baseline reusable components:

- Button
- IconButton
- Input
- Select
- TextArea
- Checkbox
- Radio
- FormField
- Card
- Badge
- StatusBadge
- Alert
- EmptyState
- ErrorState
- LoadingState
- Modal
- ConfirmDialog
- Drawer
- Tabs
- Table
- Pagination
- SearchField
- PageHeader
- Breadcrumb
- ResidentSummary
- ActorSummary
- ConnectivityStatus

---

# 8. Status semantics

Operational status must use:

- text
- icon or shape where appropriate
- optional color

Never color alone.

---

# 9. Destructive actions

Revoke or other destructive actions require:

- explicit action label
- confirmation
- clear target identity
- reason entry when backend requires it
- visible success/failure result

---

# 10. Empty states

Empty states must distinguish:

- no records exist
- no records are authorized
- filters return nothing
- backend unavailable

Do not present all empty cases as identical.

---

# 11. Error language

Vietnamese errors should be concise and actionable.

Examples:

401:
"Phiên làm việc chưa được xác định. Vui lòng đăng nhập lại."

403:
"Bạn không có quyền thực hiện thao tác này."

404:
"Không tìm thấy dữ liệu phù hợp hoặc bạn không có quyền truy cập."

409:
"Dữ liệu hiện tại xung đột với thao tác này. Vui lòng kiểm tra lại."

Network:
"Không thể kết nối tới hệ thống. Vui lòng kiểm tra kết nối."

---

# 12. Navigation wording

Initial navigation labels:

- Tổng quan
- Người cao tuổi
- Chăm sóc
- Thuốc
- Lâm sàng
- Sự cố
- Nhân sự & phân quyền
- Hỗ trợ AI
- Báo cáo
- Trạng thái hệ thống

Visibility is role-based.

---

# 13. Mobile behavior

On mobile:

- left sidebar becomes compact navigation/drawer
- primary actions remain reachable
- tables may transform into cards
- critical resident information stays visible
- no horizontal scrolling for primary workflows unless unavoidable

---

# 14. Design review rule

No feature UI may introduce a new interaction pattern when an accepted shared
component can express it safely.
