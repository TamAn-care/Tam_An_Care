# Tâm An Care V7.6 — Phase 2 Scope + Gap Closure Design

## Release theme

**Operational Care Workspace**

V7.6 will deepen and unify the existing operational-care workflow rather than attempting to expose every backend module at once.

## Scope principles

1. Preserve frozen V7.5.
2. Reuse proven backend capability before adding new backend surface.
3. Treat infrastructure and authorization helpers as non-UI domains.
4. Treat `throw new Error(...)` as defensive behavior unless evidence shows an unfinished implementation.
5. Explicit NOT_IMPLEMENTED/TODO/FIXME/stub markers require targeted review.
6. Keep V7.6 bounded to one coherent operational workflow.

## V7.6 in scope

- Dashboard enhancement
- Resident Care View enhancement
- Care work management UI
- Care Actions workflow
- Care Plans / governance integration where contract is proven
- Care Tasks / execution integration where contract is proven
- Warning Review integration
- Human actor propagation
- Resident access-scope enforcement
- Responsive desktop/tablet/mobile UI

## Deferred from V7.6

- Full clinical observations workspace
- Full incident management workspace
- Full medication workspace
- Individual daily-care domain workspaces
- Advanced AI implementation

## Acceptance contract

- Frozen V7.5 production remains unchanged during development.
- V7.6 development occurs only in isolated V7.6 workspace/runtime.
- All new frontend API calls use the authoritative backend routes.
- Human actor identity propagates through every protected workflow.
- No protected operation succeeds without an authorized actor.
- Resident access scope is enforced before resident-specific data/actions.
- Care actions can be listed/viewed and workflow state is visible.
- Assignment and transfer preserve actor/audit history.
- Start-review, resolve and reopen preserve authorization rules.
- Care-plan governance is exposed only where backend contract is proven.
- Care-task execution is exposed only where backend contract is proven.
- Warning review workflow integrates with resident operational care.
- Dashboard and resident care-view remain backward compatible.
- Staff Access remains backward compatible.
- Desktop, tablet and mobile layouts pass responsive acceptance.
- All API error states render safely without destructive UI behavior.
- Database schema changes are prohibited unless separately gated.
- Functional acceptance uses disposable isolated database fixtures.
- Active production database receives no acceptance-test fixtures.
- Rollback artifact is created before any future production cutover.
- Exact source/build/image hashes are locked before promotion.
- Production cutover occurs only after integrated E2E acceptance.
