## SQL implementation rule

state/status filters and LIMIT values must be derived only from
the database/source contracts discovered by this Step 8A.E2 gate.

## DI implementation rule

Step 8A.E must reuse the existing database-provider pattern and
must not create a second independent database architecture.

Integration wiring must avoid circular module dependencies.

Where direct service reuse would create circular ownership or
cross-domain coupling, a minimal read-only adapter is preferred.

## Performance rule

- bounded queries only
- deterministic ordering
- fixed maximum result sets
- no per-row follow-up queries
- no N+1
- no unbounded audit reads
- no domain-wide scans
- stateless request handling

- prescribe

- change medication state
- close incidents
- create clinical observations
- alter care tasks
- alter care plans
- perform safeguarding action
- perform restraint
- initiate hospital transfer
- perform autonomous clinical action
