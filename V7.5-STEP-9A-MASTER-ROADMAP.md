# TAM AN CARE V7.5
## MASTER ROADMAP — APPLICATION / UI COMPLETION & OPERATIONAL USABILITY

Status: LOCKED BY STEP 9A

---

# 1. Release objective

V7.5 converts the accepted V7.4.3 backend foundation into a complete
operational application that a non-programmer can use through a graphical
interface without relying on Terminal commands.

The V7.4.3 backend remains the protected baseline.

V7.5 focuses first on usability, workflow completion, frontend integration,
operational safety and packaging.

---

# 2. Primary user outcome

At V7.5 completion, an authorized user must be able to operate the main
Tâm An Care workflows from the application interface.

Terminal access must not be required for ordinary daily operation.

---

# 3. V7.5 execution order

## STEP 9A — ROADMAP & SCOPE LOCK
Design only.
No application code.

## STEP 9B — FRONTEND ARCHITECTURE & DESIGN SYSTEM
Lock:
- frontend framework
- application shell
- navigation
- layout
- responsive strategy
- state management

Must include:
- resident navigation

- attention items

Supervisor-facing UI for:

- care plans
- care tasks
- clinical observations
- medication
- incidents

changes.

- nutrition / hydration

- personal care

- sleep / rest

Requirements:
- human review boundary

- governance status visibility

---

# 4. Priority rule

V7.5 uses this priority:

1. usable application
2. existing backend integration
3. operational safety
4. workflow completeness
5. responsive usability
6. packaging
7. additional backend expansion only when proven necessary

---

# 5. Non-programmer optimization rule

Every implementation step must prefer:

- one copy/paste command block
- automatic preflight
- fail-closed behavior
- automatic cleanup where safe
- exact PASS/STOP output
- automatic rollback for runtime replacement
- no manual source editing
- no manual database editing
- no manual Docker reconstruction

---

# 6. Change-control rule

No step may modify an earlier accepted baseline without:

1. preflight
2. exact change scope
3. backup
4. implementation
5. build
6. isolated acceptance
7. controlled cutover
8. active acceptance
9. closure

---

# 7. Production rule

V7.5 development does not modify production unless a later explicitly
approved production release gate is opened.

---

# 8. Definition of V7.5 success

V7.5 is complete only when:

- main workflows are usable through GUI
- normal operation does not require Terminal
- canonical staff identity is respected
- resident authorization is respected
- role-based navigation is enforced
- operational dashboard is usable
- staff/access administration is usable
- core care workflows are usable
- UI handles errors and empty states safely
- responsive application is accepted
- macOS package is accepted
- rollback is proven
- final release manifest is frozen
