# TAM AN CARE V7.4.3
# STEP 7L.5 — CARE PLAN HUMAN AUTHORIZATION

## Principle

A Care Plan is a human-accountable care governance object.

AI may recommend a plan or proposed modification.

AI and SYSTEM actors must never autonomously:
- activate a Care Plan;
- suspend a Care Plan;
- complete a Care Plan;
- cancel a Care Plan.

## Canonical states

DRAFT
ACTIVE
SUSPENDED
COMPLETED
CANCELLED

## Canonical human-controlled transitions

DRAFT -> ACTIVE
ACTIVE -> SUSPENDED
SUSPENDED -> ACTIVE
ACTIVE -> COMPLETED
DRAFT -> CANCELLED
ACTIVE -> CANCELLED
SUSPENDED -> CANCELLED

## Authorization

CARE_MANAGER:
- activate
- reactivate
- suspend
- complete
- cancel

SUPERVISOR:
- activate
- reactivate
- suspend
- complete
- cancel

CAREGIVER:
- denied plan governance transitions

AI:
- denied

SYSTEM:
- denied

## Concurrency

All state-changing transitions must:
1. execute inside one database transaction;
2. lock the Care Plan row before authorization;
3. evaluate current status after row lock;
4. authorize a human actor;
5. perform exactly one valid transition;
6. insert exactly one audit event;
7. guarantee that concurrent attempts produce exactly one winner.

## Audit events

PLAN_ACTIVATED
PLAN_SUSPENDED
PLAN_REACTIVATED
PLAN_COMPLETED
PLAN_CANCELLED

## AI boundary

AI recommendation = allowed.

AI plan governance decision = not allowed.

Autonomous clinical action = false.
