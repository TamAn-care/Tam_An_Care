# Tam An Care V7.4.3

## Development Milestone

V7.4.3 extends the known-good V7.4.2 baseline.

Production V7.4.2 remains frozen.

---

## 1. Care Action Workflow

Implement the complete human-controlled workflow:

AI Early Warning

→ Human Review

→ Care Action Creation

→ Assignment

→ Acceptance

→ Execution

→ Completion

→ Audit

AI must not autonomously execute clinical actions.

---

## 2. Resident Context

Care Actions and Early Warnings must support association
with a specific resident.

Resident context should support future integration with:

- resident profile
- health observations
- room / bed
- care plan
- assigned staff
- health history

---

## 3. Human-in-the-loop

AI recommendations remain advisory.

Human authorization is required for care actions.

The system must retain:

- actor identity
- timestamps
- action history
- status transitions
- audit records

---

## 4. Operational Dashboard

Prepare backend/UI capability for:

- active warnings
- warning severity
- open care actions
- assigned staff
- overdue actions
- completed actions
- human review status

---

## 5. Safety and Governance

Preserve V7.4.2 principles:

- AI kill switch
- AI governance
- risk classes
- human review
- auditability
- no autonomous clinical action

---

## 6. Compatibility

V7.4.3 must preserve:

- existing AI engines
- AI governance endpoints
- Early Warning engine
- Care Action contracts
- production database integrity
- existing UI compatibility

---

## Development Rule

No V7.4.3 component may use the production PostgreSQL
database during development or testing.

V7.4.3 must use an isolated development database.

---

## Release Strategy

V7.4.3 development

→ isolated build

→ isolated database

→ functional testing

→ regression testing

→ release candidate

→ pre-cutover backup

→ controlled cutover

Only after all gates pass may V7.4.3 replace V7.4.2.
