# Tam An Care V7.4.3 — Step 8D.A

## Resident Assignment Scope / Authorization Boundary

### Status

Discovery and design-input gate only.

No source implementation is authorized by this step.

### Locked incoming security state

Current Step 8B / Step 8C operational security is:

- server-side human role authorization
- CAREGIVER / NURSE / SUPERVISOR
- AI / SYSTEM denied
- ROLE_GATE_ONLY
- full resident assignment scope deferred

### Objective

Determine whether Tam An Care already possesses a canonical
resident-to-human assignment or responsibility model that can be reused
for operational access control.

### Required architectural decision before implementation

One and only one of the following may be selected after discovery:

1. REUSE_EXISTING_ASSIGNMENT_MODEL
2. EXTEND_EXISTING_ASSIGNMENT_MODEL
3. CREATE_MINIMAL_CANONICAL_RESIDENT_ACCESS_MODEL
4. DEFER_SCOPE_ENFORCEMENT_IF_IDENTITY_MODEL_IS_INSUFFICIENT

### Mandatory security principles

- server-side authorization
- fail closed
- no client-side-only filtering
- no trust in arbitrary residentId
- AI / SYSTEM receives no human authority
- role authorization remains necessary but may not be sufficient
- assignment scope must not create clinical authority
- assignment scope must not create medication authority
- assignment scope must not create incident authority
- assignment scope must not create care-plan mutation authority
- assignment scope must not create care-task mutation authority

### Resident visibility target

A human actor should only read residents permitted by the canonical
authorization model.

SUPERVISOR broader visibility may only be introduced if explicitly
defined by the final authorization contract.

### Read-model requirements

Step 8B care-view and Step 8C dashboard must ultimately share the same
canonical resident visibility rule.

They must not implement two divergent assignment rules.

### Performance requirements

Authorization must support set-based filtering.

Forbidden:

- N+1 authorization queries
- one assignment query per resident
- loading unbounded assignment history
- loading audit history for normal authorization

### Persistence principle

Do not create a new assignment table if an existing canonical model
already satisfies resident-scope authorization.

### Audit principle

Authorization decision provenance must be explainable, but normal read
authorization must not generate high-volume business audit writes unless
explicitly designed in a later contract.

### Next gate

Step 8D.B must convert discovery findings into an exact authorization
model, DTO/security behavior, query strategy and persistence decision.

Implementation is forbidden before Step 8D.B is locked.
