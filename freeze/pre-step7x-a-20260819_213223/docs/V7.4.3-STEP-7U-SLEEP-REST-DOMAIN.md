# Tam An Care V7.4.3 — Step 7U
## Sleep / Rest / Night-time Safety Management

### Purpose

Provide an auditable and human-accountable domain for:

- sleep/rest care preferences
- normal sleep routine
- bedtime and wake-up preferences
- factual sleep observation
- night-time monitoring
- waking episodes
- night-time restlessness
- nocturia / toileting-related waking as an observation only
- night-time mobility and fall-safety concerns
- human non-pharmacological support
- safety alert
- escalation
- audit

### Core principles

1. Sleep observation is not diagnosis.
2. The system does not diagnose insomnia, sleep apnea,
   circadian disorder, delirium or psychiatric disorder.
3. Human care preferences and resident dignity are preserved.
4. Normal sleep should not be disrupted unnecessarily.
5. Night checks should be proportionate to the resident's
   approved human care plan and safety needs.
6. AI is advisory only.
7. AI may detect patterns but cannot prescribe interventions.
8. Medication, sedative, restraint, isolation and clinical
   treatment decisions remain human-controlled.
9. Official mutations require attributable human actors.
10. State mutation requires transaction + row lock +
    post-lock state validation.
11. Incompatible concurrent mutation = single winner.
12. Loser mutation = zero business mutation + zero audit.
13. Cross-domain mutation is never autonomous.

### Domain flow

Resident
-> Human Sleep / Rest Care Plan
-> Night Monitoring / Sleep Observation
-> Optional Sleep / Rest Event
-> Human Support Response
-> Optional Safety Alert
-> Human Escalation
-> Human Review / Resolution
-> Follow-up
-> Audit

### Explicit exclusions

This domain does NOT autonomously:

- diagnose insomnia
- diagnose sleep apnea
- diagnose delirium
- diagnose dementia
- diagnose psychiatric disorder
- prescribe sleep medication
- administer PRN sedative
- modify medication dose
- order physical restraint
- order chemical restraint
- impose isolation
- force sleep
- force wake-up
- transfer resident
- call emergency service
- create an official incident
- create care task
- create care action
