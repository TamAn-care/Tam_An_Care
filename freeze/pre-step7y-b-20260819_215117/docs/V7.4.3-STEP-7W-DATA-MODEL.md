# Step 7W — Canonical Data Model

Exactly eight tables are designed.

## 1. infection_control_plans

Human-authored prevention / infection-control care plan.

Lifecycle:
DRAFT -> REVIEWED -> ACTIVE -> RETIRED

Contains approved resident-specific preventive considerations,
not autonomous treatment instructions.

## 2. infection_observations

Factual human-recorded infection-related observations.

Examples:

- temperature observation
- cough observation
- respiratory symptom observation
- urinary symptom report
- gastrointestinal symptom report
- fatigue
- change from baseline
- resident-reported discomfort

Observation != diagnosis.

Lifecycle:
RECORDED -> VERIFIED -> AMENDED

## 3. exposure_events

Human-recorded possible exposure or contact context.

Examples:

- close contact
- shared room exposure
- visitor exposure
- staff exposure
- community exposure
- facility cluster context

Exposure event != confirmed infection.

Lifecycle:
OPEN -> REVIEWED -> CLOSED

## 4. infection_precautions

Human-authorized infection-control precaution record.

Examples:

- enhanced hand hygiene
- PPE instruction
- room-placement precaution
- contact precaution
- droplet precaution
- respiratory hygiene measures

Precaution requires human authority.

AI cannot activate or discontinue precaution.

## 5. infection_monitoring_records

Append-only surveillance / monitoring observations after review.

Supports longitudinal monitoring.

Verified records are not overwritten.

## 6. infection_alerts

Human-confirmed infection safety alert.

Examples:

- significant change from baseline
- concerning symptom cluster for human review
- exposure requiring review
- persistent symptom pattern

AI alert remains advisory until human confirmation.

## 7. infection_escalations

Human escalation workflow.

Lifecycle:
OPEN -> ASSIGNED -> ACCEPTED -> RESOLVED

Reviewer identity must be preserved.

## 8. infection_audit

Append-only attributable audit history.

Requirements:

- same transaction as business mutation
- unique sequence per entity
- human attribution
- failed mutation = zero audit
- losing concurrent mutation = zero audit
