# Step 7X — Canonical Data Model

Exactly eight Step 7X governance tables are designed.

## 1. medication_reconciliations

Human medication reconciliation episode.

Typical contexts:

- admission
- return from hospital
- transfer
- significant medication-list review
- discharge preparation where applicable

Lifecycle:
DRAFT -> REVIEWED -> COMPLETED

Reconciliation itself never mutates medication_orders.

## 2. medication_reconciliation_items

Append-only medication/source comparison items.

May document:

- documented medication
- source
- dose text
- route text
- frequency text
- discrepancy type
- discrepancy notes

Discrepancy != medication change.

## 3. medication_order_reviews

Human governance review referencing an existing medication_order.

Lifecycle:
PENDING -> REVIEWED

Review does not independently edit the medication order.

## 4. medication_safety_checks

Human readiness / safety check associated with an existing order,
schedule or intended administration context.

Examples:

- resident identity confirmed
- order context reviewed
- known allergy information reviewed
- route context reviewed
- administration readiness reviewed

This is governance, not autonomous authorization.

## 5. high_risk_medication_checks

Independent human double-check governance.

High-risk designation comes from approved policy configuration,
not AI inference and not hardcoded treatment rules.

Requirements:

- first checker = human
- second checker = human
- first checker != second checker
- AI cannot be either checker
- SYSTEM cannot be either checker

## 6. medication_administration_exceptions

Human-recorded exception related to expected administration.

Examples:

- held under authorized instruction
- refused
- omitted
- unavailable
- delayed
- other documented exception

Exception record does not itself prescribe a clinical action.

## 7. medication_adverse_reaction_observations

Human factual observation of a possible adverse medication-related event.

Observation != diagnosis.

May trigger human review / escalation but cannot change medication.

## 8. medication_safety_audit

Append-only medication-safety governance audit.

Requirements:

- same transaction as Step 7X mutation
- attributable human actor
- unique sequence per entity
- failed mutation = zero audit
- losing concurrent mutation = zero audit
