======================================================================
10. OUTBOUND CONCURRENCY CONTRACT
======================================================================

PROBLEM:

There is intentionally no authoritative balance row to
SELECT ... FOR UPDATE.

Therefore concurrent outbound transactions cannot safely
use:

  SELECT SUM(...)
  IF balance sufficient
  INSERT issue

without serialization.

LOCKED IMPLEMENTATION STRATEGY:

Within ONE PostgreSQL transaction:

1. validate canonical ACTIVE human actor
2. validate inventory item
3. validate lot/item relation if lot supplied
4. validate transaction unit == item.base_unit
5. acquire transaction-scoped PostgreSQL advisory lock
6. calculate authoritative signed ledger balance
7. reject outbound if resulting balance < 0
8. INSERT immutable inventory transaction
9. COMMIT

LOCK KEY:

  deterministic inventory accounting key

For non-lot movement:
  INVENTORY_ITEM:<inventory_item_id>

For lot movement:
  INVENTORY_ITEM_LOT:<inventory_item_id>:<inventory_lot_id>

PostgreSQL mechanism:

  pg_advisory_xact_lock(...)

Requirements:

  -> transaction-scoped
  -> automatically released at commit/rollback
  -> all outbound service paths MUST use same key contract
  -> no application in-memory mutex
  -> no second balance table
  -> no race between concurrent outbound transactions

11. LOT VALIDATION CONTRACT
======================================================================

IF item.lot_tracking_required = true:

  outbound inventory transaction:
    inventory_lot_id REQUIRED

  inbound receipt:
    inventory_lot_id REQUIRED

IF item.lot_tracking_required = false:

  inventory_lot_id MAY be NULL

IF lot supplied:

  lot.inventory_item_id
    MUST equal transaction.inventory_item_id

OUTBOUND lot status:

  ACTIVE required

FOR NORMAL ISSUE:

  expired lot forbidden

QUARANTINED:
  normal outbound resident use forbidden

EXHAUSTED/CLOSED:
  new normal outbound forbidden


======================================================================
12. UNIT CONTRACT
======================================================================

OPS-2-B supports NO unit conversion.

Therefore:

inventory_transactions.unit
  MUST equal
inventory_items.base_unit

Examples:

item base_unit = "cái"
transaction unit must = "cái"

item base_unit = "ml"
transaction unit must = "ml"

Future pack/unit conversion:
  separate explicit contract only.


======================================================================
13. IDEMPOTENCY CONTRACT
======================================================================

A source-backed transaction uses:

  source_domain
  source_entity_type
  source_entity_id
  inventory_item_id
  inventory_lot_id / NULL

Existing migration unique index:
  uq_inventory_tx_source_item_lot

Duplicate transaction:
  HTTP 409

No silent second stock movement.

Manual transaction without source entity:
  source_entity_type = NULL
  source_entity_id = NULL

and is not covered by source idempotency index.


======================================================================
14. IMMUTABLE LEDGER CONTRACT
======================================================================

inventory_transactions:

  INSERT = authoritative movement

  UPDATE = FORBIDDEN
  DELETE = FORBIDDEN

Correction:

  create explicit compensating movement.

Examples:

incorrect ISSUE 5:
  compensate RETURN_IN 5
  then create correct ISSUE quantity

incorrect RECEIPT:
  compensate ADJUSTMENT_OUT / RETURN_OUT
  according to governance reason.

Original transaction always remains historical evidence.
